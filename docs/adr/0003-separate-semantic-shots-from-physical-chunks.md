# ADR 0003: Separate semantic shots from physical H3 chunks

- Status: Accepted
- Date: 2026-09-28

## Context

HR Endless Sampler compiles one semantic MiniMax H3 prompt plan and samples it through overlapping physical chunks. A semantic shot represents an intentional camera cut and owns the guide-defined `[Shot N]` timeline. A physical chunk is only an internal sampling window.

The previous chunk-local prompt compiler conflated these boundaries. It rendered overlapping semantic regions as new local shots, used shot-transition language around physical boundaries, repeated negative control text in `summary` and `retention_analysis`, and independently sliced dialogue text for each chunk. Runtime logs showed dialogue gaps, word-internal splits, false `<scenetrans>` markers, repeated actions, and contradictory sound fields.

The MiniMax prompt guides reserve `[Shot N]`, cut language, and `<scenetrans>` for real cinematic shot transitions. They also define six full-reference sections with separate responsibilities.

## Decision

1. Keep semantic shot boundaries and physical chunk boundaries as separate concepts.
2. Use `[Shot N]`, explicit camera-cut language, and `<scenetrans>` only when a physical chunk actually contains a semantic shot boundary.
3. Represent a physical continuation within one semantic shot as the same established shot, without inventing a cut.
4. Assign every utterance one continuous global frame interval after its visible speaker is established. Physical chunks project that interval but cannot introduce gaps or restart the utterance.
5. Compute deterministic dialogue text spans once from the global utterance timeline. Prefer sentence, clause, whitespace, and natural phrase boundaries; never independently reslice text in each physical chunk.
6. Render dialogue with three physical states: begin, continue, and complete. Only begin introduces the speaker; only continue carries the established voice; complete must not claim continuation into another chunk.
7. Use `<scenetrans>` only for dialogue crossing an actual semantic shot cut. Use `<cutoff>` only when the target video ends before speech completes.
8. Keep the six full-reference fields within their guide-defined responsibilities:
   - `subject_definitions`: active reference identities and sources.
   - `summary`: a short task and current-content summary.
   - `retention_analysis`: reference preservation relationships only.
   - `detailed_description`: playback-order camera, state, action, dialogue, and synchronized sound.
   - `overall_soundscape`: non-verbal ambience and physical sounds in complete English sentences.
   - `non_diegetic_music`: audience-only score or `N/A`.
9. Keep private `asset_N` entity IDs out of final H3 prose. Only canonical `<Subject N>`, `<Picture N>`, `<Video N>`, and `<Audio N>` labels may cross the compiler boundary.
10. Describe action continuity as positive observable state progression. Use short prohibitions only when necessary to prevent a demonstrated replay failure.
11. Validate each final chunk prompt before H3 sampling for dialogue coverage, transition-marker legality, reference-label integrity, field responsibility, sound/music consistency, and private entity leakage.
12. Do not change sampler inputs, joint AV latent conditioning, overlap assembly, replay interfaces, or ComfyUI core.

## Consequences

- Changing `chunk_frames` changes physical request boundaries but not the semantic story, dialogue order, shot cuts, or final concatenated spoken text.
- Prompt generation becomes deterministic with respect to one frozen global plan.
- Chunk prompts become shorter and place more attention on current visible and audible content.
- Existing replay prompts generated by the conflated implementation are invalid validation artifacts; new runs must begin from Chunk 1.
- Validation may reject malformed plans before expensive sampling instead of allowing ambiguous H3 output.

## Alternatives rejected

- **Repeat the complete utterance in every intersecting chunk:** caused speech restarts and overlapping speakers.
- **Slice dialogue independently by chunk percentage:** produced gaps and word-internal fragments.
- **Treat every physical chunk as a new shot:** violates the guide and induces false camera/audio transitions.
- **Repair continuity with PCM mixing:** cannot correct contradictory visual or dialogue instructions and is outside the prompt-layer ownership boundary.
- **Add new public chunk/shot controls:** unnecessary; the existing global plan and internal chunk plan contain the required timing information.
